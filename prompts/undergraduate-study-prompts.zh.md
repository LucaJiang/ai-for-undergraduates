# 本科生 AI 学习提示词模板

这些模板用于讨论课程内容，不用于代交必须独立完成的作业。使用前先查看课程要求；模板本身不保证回答准确。

**角色 + 背景 + 限制 + 格式**是一份检查清单，不是要求你写四段长文。简单问题用一句话也可以说清楚。设定角色有助于调整回答方式，并不让模型自动成为合格或不会出错的专家。

遇到新内容，需要解释或完整例题时，选择**讲解**；需要提示、回忆练习或对自己尝试的反馈时，选择**练习**。涉及实际操作的请求还需要明确范围、权限和核查步骤，最后一个可选模板就是这种情况。

替换所有方括号，只使用获准分享的材料。至少留一步由自己完成，并独立核查重要结论。这个网站不会保存对话，也不会把提示词发给 AI 服务。

## 01. 理解一个难懂的概念

类别: 理解概念

模式: 讲解

适用场景: 第一次接触一个不熟悉的概念。

填写内容: 主题、课程程度、已有知识，以及具体不懂的地方。

核查要点: 将解释与正式定义对照。

```text
角色：请做一位耐心的本科课程辅导老师。

背景：我正在[课程]中学习[概念]。我知道[已有知识]，但不理解[具体难点]。

限制：解释这个难点，不要介绍整个学科。使用类比时，请说明它的适用范围。

格式：给出一段简短解释和一道完整例题，再问一个检查理解的问题，等待我回答。
```

## 02. 找出缺失的基础知识

类别: 理解概念

模式: 讲解

适用场景: 总是在同一个步骤卡住。

填写内容: 卡住的步骤，以及目前的尝试。

核查要点: 将推测的知识缺口视为待检验的假设，而不是确定诊断。

```text
角色：请做一位帮助我查找知识缺口的辅导老师。

背景：我正在学习[主题]，在[步骤]卡住了。我的尝试是[尝试]。

限制：不要预设原因，也不要解出整道题。需要时先向我澄清。

格式：提出一项值得检查的前置知识，简短解释，再问一道小题，然后等待我回答。
```

## 03. 读懂幻灯片或截图

类别: 课程材料

模式: 讲解

适用场景: 无法把文字、符号和图形联系起来。

填写内容: 清晰图片，以及具体看不懂的部分。

核查要点: 对照原图检查文字识别与符号。

```text
角色：请担任[课程]的助教。

背景：这是我的课程幻灯片。我是[年级/专业]的学生，对[具体部分]感到困惑。

限制：不要猜测看不清的文字。区分幻灯片原本写出的内容与你补充的解释。

格式：把主要观点、符号和图形联系起来，用一个小例子说明，再问我一个问题。
```

## 04. 围绕选定的 Notebook 材料学习

类别: 课程材料

模式: 不限

适用场景: 复习一组范围明确的课程材料。

填写内容: 选定与问题有关的材料标题。

核查要点: 打开引用，确认原文确实支持相应结论。

```text
角色：请做一位依据原始材料回答的学习助手。

背景：只使用[选定的讲义/阅读材料]回答[问题]。

限制：材料不足时请说明。宁可少列几项，也不要编造。请标明推断。

格式：整理最多五个有材料支持的要点，注明原文位置。出一道测验题，不给答案，等待我回答。
```

## 05. 主动回忆练习

类别: 回忆自测

模式: 练习

适用场景: 复习已经学过的内容。

填写内容: 主题、课程程度，以及讲义或学习目标。

核查要点: 对照原文检查反馈；与 AI 意见不同，不一定是你错了。

```text
角色：请担任出题老师和辅导老师。

背景：我正在为[课程]复习[主题]。请使用[提供的材料/学习目标]。

限制：每次只问一道题，先隐藏答案。我的回答正确时，不要编造错误。

格式：等待我的尝试。若有错误，指出最先出问题的地方并给一个提示；若正确，说明原因并提供一道更难的题。
```

## 06. 选择题练习

类别: 回忆自测

模式: 练习

适用场景: 区分容易混淆的概念。

填写内容: 讲义、主题和难度。

核查要点: 检查是否只有一个选项正确。

```text
角色：请担任课程出题老师。

背景：我正在用[讲义]学习[程度]的[主题]。

限制：暂时不给答案。避免歧义和虚构事实；材料较少时，可以减少题目数量。

格式：最多出五道选择题，设置合理的干扰选项。等待我选择，再依据材料解释各个选项。
```

## 07. 作业提示

类别: 推理解题

模式: 练习

适用场景: 对已经尝试过的题目，获取课程允许的帮助。

填写内容: 题目和自己的尝试；先检查考核要求。

核查要点: 确认提示没有违反独立完成作业的要求。

```text
角色：请用引导式提问帮助我学习。

背景：题目是[题目]。我已经尝试了[尝试]，卡在[步骤]。

限制：不要给完整解答，也不要写可直接提交的文字。如果我的尝试正确，请直接说明。

格式：检查我的尝试，给一个有针对性的提示，再问我下一步想怎么做，然后等待。
```

## 08. 检查我对概念的解释

类别: 反馈修改

模式: 练习

适用场景: 检验自己已经写出的解释。

填写内容: 自己的段落，以及合适的来源或定义。

核查要点: 根据证据决定采纳或不采纳每一条建议。

```text
角色：请做一位认真核查的辅导老师，不要代写。

背景：这是我对[概念]的解释：[文字]。请对照[来源/定义]检查。

限制：不要重写，不要编造错误，也不要要求补充与我目标无关的内容。

格式：先说明哪些地方正确。如有错误，引用相应部分并解释原因。问一个检查理解的问题，等待我自己修改。
```

## 09. 比较两个模型的回答

类别: 核查来源

模式: 不限

适用场景: 模型意见不同，或对同一问题给出不同解释。

填写内容: 同一个问题、两份回答和原始材料。

核查要点: 模型的比较仍是暂时判断；需要在模型之外核查。

```text
角色：请做一位审慎的比较助手。

背景：问题：[问题]。回答 A：[文字]。回答 B：[文字]。来源：[材料]。

限制：不要根据篇幅、语气自信程度或多数表决选择答案。标明证据无法核查的部分。

格式：比较主张、假设、清晰程度和来源支持。指出一个值得我独立调查的分歧。
```

## 10. 根据课程大纲安排学习

类别: 学习规划

模式: 不限

适用场景: 安排未来两周的课程学习。

填写内容: 大纲、日期、可用时间、不能学习的日期和已掌握内容。

核查要点: 不要把编造的日期或推测的先后关系当成课程要求。

```text
角色：请帮助我制定本科课程学习计划。

背景：课程大纲和日期：[粘贴]。可用时间：[小时数]。无法安排的日期：[日期]。已经掌握：[主题]。

限制：缺少时间安排信息时先询问。不要编造截止日期。区分明确的课程要求与建议的知识先后关系。

格式：制定两周计划，包括前置知识、可行的学习时段，以及每个主题的一项自测。
```

## 11. 梳理讲义中的概念联系

类别: 课程材料

模式: 讲解

适用场景: 课后重新组织笔记。

填写内容: 一小段原始材料，以及本课学习目标。

核查要点: 检查箭头或概念联系是否确有材料支持。

```text
角色：请担任课程助教。

背景：请围绕[学习目标]，使用以下讲义：[讲义]。

限制：不要只是逐页压缩，也不必凑固定数量。请标明推断出的联系。

格式：梳理最多五个概念，包括定义、机制、假设或推论。注明原文位置，再给一道回忆题。
```

## 12. 中英双语术语表

类别: 课程材料

模式: 讲解

适用场景: 用中文辅助理解英语授课内容。

填写内容: 主题、材料，以及偏好的中文术语或繁简体。

核查要点: 对照课程材料检查学科专用术语。

```text
角色：请做一位中英双语学术辅导老师。

背景：我用英语学习[主题]。请用[繁体/简体]中文辅助，并采用提供的课程术语。

限制：不要机械直译，也不要编造官方译名。请标明有歧义的术语。

格式：用表格列出英文术语、中文术语、简单英语解释、例子，以及可能的混淆。
```

## 13. 证明题提示模式

类别: 推理解题

模式: 练习

适用场景: 已经尝试、且允许获得辅助的证明练习。

填写内容: 命题、允许使用的定义和方法、证明尝试，以及卡住的地方。

核查要点: 有效提示应保留题目的假设和定义域。

```text
角色：请做一位证明题辅导老师。

背景：命题：[命题]。我的尝试：[尝试]。允许使用的方法：[方法]。

限制：不要给出完整证明。检查命题按原文表述是否成立，不要编造错误。

格式：给出一个有用的定义或提示，并问一个帮助我进行下一步的问题，等待我回答。
```

## 14. 调试自己写的代码

类别: 推理解题

模式: 练习

适用场景: 理解程序错误。

填写内容: 最小代码示例、预期输出、实际输出和报错信息。

核查要点: 运行最小测试，并检查具体改了什么。

```text
角色：请做一位编程辅导老师。

背景：我写了[代码]，预期得到[结果]，实际得到[结果/错误]，正在学习[概念]。

限制：不要替换整个程序，也不要完成整份作业。信息不足时请询问。

格式：解释相关的程序行为，建议最小修改和一个测试。先让我尝试，再提出更多修改。
```

## 15. 规划分析，而不是代写报告

类别: 学习规划

模式: 不限

适用场景: 在课程允许的分析任务开始前讨论方法。

填写内容: 研究问题、变量定义、研究设计和评分标准；不要提供敏感原始数据。

核查要点: 向老师确认研究设计、假设和课程要求。

```text
角色：请做一位数据分析指导老师。

背景：研究或作业问题：[问题]。研究设计：[设计]。变量：[定义]。评分标准：[标准]。

限制：不要运行分析，也不要撰写报告。不要从关联推断因果关系。

格式：选择方法前，先提出关键的设计问题。给出初步计划，以及假设和数据质量的检查项。
```

## 16. 写作反馈

类别: 反馈修改

模式: 练习

适用场景: 修改自己撰写、且允许获得反馈的草稿。

填写内容: 自己的文字、希望表达的主张和评分要求。

核查要点: 自己完成修改，并确认没有加入未经核查的主张。

```text
角色：请做一位写作指导老师。

背景：我的段落：[文字]。希望表达的主张：[主张]。评分标准：[要求]。

限制：不要重写段落，也不要增加主张或引用。如果逻辑合理，请直接说明。

格式：指出不清楚的措辞或缺乏支持的衔接，解释为什么重要，再请我修改其中一处。
```

## 17. 对照来源核查一项主张

类别: 核查来源

模式: 不限

适用场景: 检查证据是否支持某个说法。

填写内容: 准确的主张和原始材料。

核查要点: 自己打开来源；“缺乏支持”不等于“错误”。

```text
角色：请做一位来源核查助手。

背景：主张：[主张]。原始材料：[粘贴/上传]。

限制：不要编造参考文献、引文或页码。证据不足时请说明。

格式：列出主张、对应原文及位置、得到支持或尚未证实、局限，以及下一步核查方法。
```

## 18. 准备答疑时要问的问题

类别: 学习规划

模式: 不限

适用场景: 把模糊的困惑整理成适合向老师提出的问题。

填写内容: 自己的理解、尝试和卡住的地方。

核查要点: 摘要是否准确反映了你实际做过的尝试？

```text
角色：请做一位学习指导老师。

背景：我理解了[概念]，尝试过[尝试]，但卡在[具体位置]。

限制：不要解决整个问题，也不要假装我做过没有做过的步骤。

格式：概括知识缺口，提出最多三个具体问题，并建议一件答疑前可以先尝试的小事。
```

## 19. 协调小组项目

类别: 学习规划

模式: 不限

适用场景: 规划团队工作，而不是代做考核内容。

填写内容: 已商定的角色、可用时间、截止日期和项目要求。

核查要点: 与所有组员确认分工，不要提供私人细节。

```text
角色：请做一位项目规划助手。

背景：项目：[任务]。成员角色及可用时间：[不含敏感信息的摘要]。截止日期：[日期]。

限制：不要撰写项目内容，也不要替他人作有约束力的决定。

格式：建议任务、依赖关系、用时估计和会议议程。将分工标为需要小组共同确认的建议。
```

## 20. 用小工具检验概念

类别: 互动探索

模式: 不限

适用场景: 可选的操作型任务，而不是普通课程问答。

填写内容: 概念、假设、允许的输入与工具，以及独立算出的已知案例。

核查要点: 运行前检查代码，并与已知答案比较。

```text
角色：请做一位教学工具设计者。

背景：目标是演示[概念]。输入：[合成数据/公开示例]。已知案例：[手算结果]。

限制：不要使用私人数据、访问网络、修改文件或提交作业。说明假设和未定义的情形。

格式：先提出最小工具方案和核查步骤。等待我同意，再生成可运行代码。在显示结果之前，先让我预测。
```
